PLUGIN_SPOTIFYSOLOIST
	EN	Spotify Soloist (Connect)

PLUGIN_SPOTIFYSOLOIST_DESC
	EN	Runs one Spotify Soloist instance per selected Squeezebox player, each its own selectable Connect device, bridges audio directly into Lyrion (no Icecast), and shows real Now Playing metadata including cover art.

PLUGIN_SPOTIFYSOLOIST_SOLOISTBIN
	EN	Path to soloist binary

PLUGIN_SPOTIFYSOLOIST_SOLOISTBIN_DESC
	EN	Full path to a manually installed Soloist executable or wrapper script. Managed updates leave this path untouched and use it as a fallback until the first managed download succeeds.

PLUGIN_SPOTIFYSOLOIST_MANAGED_UPDATES
	EN	Managed Soloist updates

PLUGIN_SPOTIFYSOLOIST_MANAGED_UPDATES_DESC
	EN	Opt in to downloading Soloist directly from Spotify's official CDN. The plugin installs a private validated copy in its persistent data directory, checks daily, and refreshes builds after 75 days. Custom executable paths are never overwritten. Spotify prohibits redistributing Soloist, so the plugin downloads it only from Spotify.

PLUGIN_SPOTIFYSOLOIST_UPDATE_NOW
	EN	Update now

PLUGIN_SPOTIFYSOLOIST_MANAGED_STATUS
	EN	Managed Soloist:

PLUGIN_SPOTIFYSOLOIST_FFMPEGBIN
	EN	Path to ffmpeg binary

PLUGIN_SPOTIFYSOLOIST_FFMPEGBIN_DESC
	EN	Used to capture each player's backend-specific audio source and feed its relay.

PLUGIN_SPOTIFYSOLOIST_AUDIOBACKEND
	EN	Audio backend

PLUGIN_SPOTIFYSOLOIST_AUDIOBACKEND_DESC
	EN	The direct-PCM shim is the default and needs no Pulse/PipeWire server. Validated x86_64, ARMv7, and ARMv8/AArch64 shims are bundled and selected from the Soloist executable architecture. PipeWire/PulseAudio remains available through the established null-sink bridge.

PLUGIN_SPOTIFYSOLOIST_SINK
	EN	PipeWire/PulseAudio sink name prefix

PLUGIN_SPOTIFYSOLOIST_SINK_DESC
	EN	Only used by the PipeWire/PulseAudio backend. Each selected player gets its own null-sink named "&lt;prefix&gt;_&lt;slot&gt;", created automatically. Soloist is launched against that sink and the bridge keeps routing/capture isolated per player.

PLUGIN_SPOTIFYSOLOIST_PCMSHIMDIR
	EN	Experimental PCM shim directory

PLUGIN_SPOTIFYSOLOIST_PCMSHIMDIR_DESC
	EN	Only used by the direct-PCM shim backend. The plugin automatically selects Bin/X86_64, Bin/ARMv7, or Bin/ARMv8_Arch64 to match the Soloist executable. Set a custom directory only to override the bundled libpulse.so.0. Each player gets its own raw-PCM FIFO automatically.

PLUGIN_SPOTIFYSOLOIST_WSPORTBASE
	EN	Control port base

PLUGIN_SPOTIFYSOLOIST_WSPORTBASE_DESC
	EN	Each player's soloist --ws / soloist ctl port is this base plus a per-player slot number. Loopback only, not reachable from the network.

PLUGIN_SPOTIFYSOLOIST_RELAYPORTBASE
	EN	Relay port base

PLUGIN_SPOTIFYSOLOIST_RELAYPORTBASE_DESC
	EN	Each player's audio relay listens on this base plus its slot number. No separate Icecast install needed.

PLUGIN_SPOTIFYSOLOIST_FORMAT
	EN	Default stream format

PLUGIN_SPOTIFYSOLOIST_FORMAT_DESC
	EN	Default format for players without an individual override in the player table above. MP3 and FLAC are encoded by ffmpeg in the bridge. PCM sends uncompressed 44.1 kHz stereo 16-bit audio in a WAV stream; with the direct-PCM shim backend it avoids ffmpeg entirely, and LMS may apply its normal per-player transcoding when a player cannot accept WAV directly.

PLUGIN_SPOTIFYSOLOIST_BITRATE
	EN	MP3 bitrate

PLUGIN_SPOTIFYSOLOIST_BITRATE_DESC
	EN	Only used when format is mp3.

PLUGIN_SPOTIFYSOLOIST_INITIALVOLUME
	EN	Initial Soloist volume

PLUGIN_SPOTIFYSOLOIST_INITIALVOLUME_DESC
	EN	Sets Soloist's volume (0-100%) once when an instance starts. Later volume changes remain local to Lyrion.

PLUGIN_SPOTIFYSOLOIST_DEVICENAMESUFFIX
	EN	Connect device name suffix

PLUGIN_SPOTIFYSOLOIST_DEVICENAMESUFFIX_DESC
	EN	Appended to each player's own Lyrion name to build its Spotify Connect device name, e.g. "Kitchen" + this suffix = "Kitchen (Soloist)" shown in the Spotify app's device picker.

PLUGIN_SPOTIFYSOLOIST_APIKEY
	EN	Soloist API key

PLUGIN_SPOTIFYSOLOIST_APIKEY_DESC
	EN	From the Spotify for Developers dashboard. Required at every Soloist startup. Shared across all per-player instances.

PLUGIN_SPOTIFYSOLOIST_RELAYBIND
	EN	Relay bind address

PLUGIN_SPOTIFYSOLOIST_RELAYBIND_DESC
	EN	0.0.0.0 (all interfaces) is usually right so other Squeezebox players on your LAN can reach it.

PLUGIN_SPOTIFYSOLOIST_AUTOSTART
	EN	Start automatically with Lyrion

PLUGIN_SPOTIFYSOLOIST_AUTOSTART_DESC
	EN	Starts a Soloist instance for every currently-selected player when Lyrion starts.

PLUGIN_SPOTIFYSOLOIST_IDLEDISCONNECT
	EN	Disconnect after pause

PLUGIN_SPOTIFYSOLOIST_IDLEDISCONNECT_DESC
	EN	Restarts the Soloist instance after this many seconds paused, clearing its metadata and briefly releasing the Spotify Connect account and stale artwork. Set to 0 to keep it continuously connected.

PLUGIN_SPOTIFYSOLOIST_STARTALL
	EN	Start all selected

PLUGIN_SPOTIFYSOLOIST_STOPALL
	EN	Stop all selected

PLUGIN_SPOTIFYSOLOIST_PLAYERS
	EN	Players

PLUGIN_SPOTIFYSOLOIST_PLAYERS_DESC
	EN	Each checked player gets its own Spotify Connect device (shown separately in the Spotify app's device picker as "&lt;player name&gt;&lt;suffix&gt;") and automatically starts playing the moment Spotify actually starts sending it audio. Unchecking a player stops and removes its instance immediately.

PLUGIN_SPOTIFYSOLOIST_RUNNING
	EN	running

PLUGIN_SPOTIFYSOLOIST_STOPPED
	EN	stopped

PLUGIN_SPOTIFYSOLOIST_RESTART_NOTE
	EN	Toggling a player's checkbox takes effect immediately (starts/stops just that instance). Saving a player's format override restarts only that selected player. Changing the default format restarts selected players that use the default; changing MP3 bitrate restarts selected players currently using MP3. A successful managed Soloist update restarts selected players automatically. Other changes to binary paths, backend settings, port bases, the sink/device prefix, or initial Soloist volume only apply the next time an instance is (re)started.

PLUGIN_SPOTIFYSOLOIST_BINARY_STALE
	EN	Soloist binary nearing expiry.

PLUGIN_SPOTIFYSOLOIST_BINARY_STALE_DESC
	EN	Spotify Soloist builds expire after about 90 days; this plugin checks the build timestamp reported by `soloist --version` and warns at 80 days.

PLUGIN_SPOTIFYSOLOIST_BINARY_STALE_LINK
	EN	Open Spotify's official Downloads and updates page.
